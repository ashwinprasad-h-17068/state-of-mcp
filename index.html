WHY REMOTE?

Lower setup friction

Remote MCP is attractive to end users because installation is easier and authentication can happen through the browser session, without manually creating credentials such as client IDs and refresh tokens.

WHY LOCAL?

More control

Local distributions are maintained by the Zoho Analytics team and contain custom logic over regular APIs. They support different development environments and preferences.

SPECIAL PACKAGING

Claude Marketplace and Plugins

Claude Marketplace

The Analytics MCP is also listed on the Claude Marketplace. Claude requires the mcp servers to be bundled in a MCPB package format. The Analytics MCPB is built over the Node.js local version.

Plugins

Plugins use a tagged Node.js-based MCP package plus an Agent skill. Because prompt bloating is not a concern in this setup, the Plugins version can expose a larger set of tools.

IDEAL ENDGOAL

Where Every Distribution Is Headed

The long-term goal is for each distribution to reach a well-defined capability tier that matches its architecture and constraints — converging on a consistent, predictable surface for developers and agents alike.

Node.js & Docker Converging

Both local (Node.js, Docker) and remote (Self-Hosted Docker) distributions will converge to the same toolset, matching what Node.js currently offers today, up through report creation and management. This covers data querying, table and workspace management, import and export, formula creation, and chart, pivot, and summary report CRUD.

Dashboard tools are deliberately excluded from this tier for two reasons. First, adding them would significantly grow the total tool count, causing prompt bloating in standard MCP clients where all tool definitions are injected into the model context at once. Second, dashboard operations are inherently more complex than other MCP tools: creating or editing a dashboard involves understanding the layout, referencing multiple reports, and managing widget configurations, making them less suitable for a flat, single-server tool list.

Note: The Claude Marketplace MCPB is built directly over Node.js and will naturally follow this same coverage boundary.

Plugins & Zoho MCP Full surface

These two distributions are not constrained by prompt bloating, each for a different architectural reason:

  • Plugins use progressive disclosure via Agent Skills - tools are surfaced to the model incrementally based on task context, so the full tool catalog is never injected all at once.
  • Zoho MCP acts as an MCP registry rather than a single monolithic server: customers compose specific tool combinations for their use case, so no single agent context receives the entire tool list.

As a result, both distributions will publish the full analytics capability surface as MCP tools, including everything available in Node.js/Docker plus dashboard creation, dashboard editing, dashboard metadata, folder management, aggregate and custom formula editing, and bulk export operations.

This makes Plugins and Zoho MCP the recommended choice for teams that need deep, end-to-end analytics automation.
